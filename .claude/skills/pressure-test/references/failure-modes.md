# Failure Modes

How this exercise produces something useless. Two lists, because analyst failures and founder failures are different and both are common.

---

## How the analysis goes wrong

**The generic register.** The default failure. Beliefs so general they would apply to any company in any industry: "customers will want this", "we can acquire efficiently", "the team can execute".

*The swap test:* replace the company name with a different one in a different industry and read it again. If it still reads as true, it is worthless and the cause is almost always an interview that stayed polite. Go back and get specifics: names, dates, exact wording, numbers and their sources.

**Listing risks instead of beliefs.** "A competitor might raise a large round" is an event that might happen. "Our head start is enough of a moat" is something the plan already assumes. Only the second is testable and only the second belongs here.

**Scoring everything in the middle.** A register where every belief sits at 7 has ranked nothing, and ranking is the entire deliverable.

**Designing tests that need the product.** Almost every belief can be tested before the thing exists. If a proposed test requires a build, look again at the library and find the version that does not.

**A test with no kill number.** Without one, every result gets read as encouraging, which is how a year passes with a great deal of activity and nothing learned.

**Testing the belief that is easiest to test.** Convenience is not a ranking criterion. Cheapness legitimately raises priority, but only among beliefs that are actually load-bearing.

**Being agreeable.** The output is only worth something if it contains at least one thing the founder did not want to write down. If everything in the register was already in the brief, the interview did not do its job, and the honest move is to say so and ask for another twenty minutes.

**Relitigating settled decisions.** The brief names what is closed. Reopening it burns credibility and attention that belong to the open questions. If a settled decision genuinely rests on a broken belief, raise it once, plainly, and let the founder decide.

**Over-length.** Fourteen sharp beliefs beat forty padded ones. Anything that would not change a decision is decoration.

## How founders fool themselves

Name these when you see them. Most are recognisable to the founder the moment they are described, which is what makes the exercise useful rather than accusatory.

**Testing the belief they most want confirmed.** Usually demand, because it is the enjoyable one and the one investors ask about. The beliefs that end companies are more often access, gatekeepers, unit economics and concentration.

**Warm evidence read as market signal.** The first customers came through the network. That proves the founder is credible to people who already know them, which is a real asset and not evidence of a channel.

**Interest counted as commitment.** Meetings booked, signups, pilots that are not paid, "we would definitely use that". None of these are money and none predict it well.

**Vanity metrics standing in for the thing.** Anything going up that is not the thing the belief is about.

**Moving the kill number after the results arrive.** The most common single failure in testing, and it is almost always unintentional: the number was never written down, so it gets remembered generously.

**Extending a test that is going badly.** A variant of the same thing. Fix the read date in advance and honour it.

**Treating a no with no reason as noise.** It is a badly asked question, and the fix is in the question rather than in the sample size.

**"We just need more conversations."** An access belief being treated as an effort problem. Ask what the last hundred contacts cost and produced.

**The unexamined constant.** Prices, terms, regulation, a partner's willingness, a key person's availability. Nobody decided these would hold, so nobody is watching them, so they score long on hidden time.

**Confusing demand with willingness to pay.** Real demand with no budget line is a slower and different sale, because a budget has to be created before anything can be bought.

**Founder time priced at zero.** It makes unit economics work at small scale and hides the fact that the model breaks when the work is done by someone who has to be paid.

**Waiting for a clean answer.** A rough result now beats a rigorous one after the runway is gone. Precision is a luxury good in an early company, and the usual cost of buying it is the company.
